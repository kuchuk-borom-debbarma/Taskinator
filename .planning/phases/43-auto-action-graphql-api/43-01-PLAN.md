# Plan 43-01: GraphQL Mutations, Queries, Connections & DataLoader

## PLANNING COMPLETE

<objective>
Expose auto-action rule management through GraphQL while preserving module boundaries: resolvers stay thin, GraphQL lists use connection/edge pagination, nested fields use DataLoader, and all domain work flows through `AutoActionService`.
</objective>

<context>
Phase 42 wired runtime task events into auto-action execution. Phase 43 completes API access for rule management. Existing GraphQL patterns live under `modular-monolith/src/graphql/schema`, `src/graphql/resolvers`, and `src/graphql/dls`. Auto-action internals already expose service methods, query helpers, validation, and execution orchestration; GraphQL must not import internal query or engine files.
</context>

<tasks>

**Type:** service

**Files:**
- `modular-monolith/src/modules/auto-action/AutoActionService.ts`
- `modular-monolith/src/modules/auto-action/internal/service/AutoActionServiceImpl.ts`
- `modular-monolith/src/modules/auto-action/internal/queries/AutoActionQueries.ts`

**Action:**
- Add small service-facing types for GraphQL pagination and mutation inputs where useful:
  - `AutoActionConnection`
  - `AutoActionListParams`
  - `CreateAutoActionInput` or equivalent service DTO
  - `UpdateAutoActionInput` or equivalent service DTO
- Add service methods:
  - `getAutoActionsByIds(ids: string[]): Promise<AutoAction[]>`
  - `getAutoActionForActor(actorId: string, id: string): Promise<AutoAction | undefined>`
  - `getAutoActionsForActorByIds(actorId: string, ids: string[]): Promise<AutoAction[]>`
  - `getAutoActionsForProjectConnection(actorId: string, projectId: string, pagination: PaginationParams): Promise<AutoActionConnection>`

  - `selectAutoActionsForProjectPage(projectId: string, pagination: PaginationParams): Promise<{ autoActions: AutoAction[]; nextCursor?: string; prevCursor?: string; totalCount: number }>` or local equivalent
- Keep raw queries internal and free of GraphQL imports.
- Enforce read/write authorization at service boundary by confirming actor access to the owning project before returning or mutating auto actions. Reuse existing project service/auth-aware lookups if available; avoid duplicating project membership SQL unless no service path exists.
- For mutation wrappers, map GraphQL-style input to existing `createAutoAction` and `updateAutoAction` payloads without exposing DB column names to GraphQL callers.

**Files:**

## 4. Add Thin Resolvers

**Type:** graphql

**Files:**
- `modular-monolith/src/graphql/resolvers/autoAction.ts`
- `modular-monolith/src/graphql/resolvers/index.ts`
- `modular-monolith/src/graphql/resolvers/jsonScalar.ts`

**Action:**
- Add `autoActionResolvers` and JSON scalar resolver, then merge both in resolver index.
- Root query `autoAction`:
  - require `context.userId`
  - call `context.loaders.autoAction.byActorIdAndId.load({ actorId: context.userId, id })`
- Root query `autoActions`:
  - require `context.userId`
  - call `autoActionService.getAutoActionsForProjectConnection(context.userId, projectId, args)`
  - return `edges`, `pageInfo`, `totalCount`
- Mutations:
  - require `context.userId`
  - delegate create/update/delete to service functions
  - return service result or payload
- Field resolvers:
  - map DB snake_case fields to GraphQL camelCase
  - `project` uses `context.loaders.project.byActorIdAndId`
  - `createdBy` and `updatedBy` use `context.loaders.user.byId`
  - timestamps return ISO strings
- Translate service errors into existing GraphQL errors where possible:
  - `UnauthorizedError`
  - `NotFoundError`
  - `MutationFailedError`

**Verify:**
- `rg "internal/queries|internal/engines" modular-monolith/src/graphql/resolvers/autoAction.ts` returns no matches.
- Resolver tests assert service/DataLoader delegation.

**Acceptance Criteria:**
- GQL-05 satisfied: no direct internal auto-action imports in resolvers.
- PAGE-02 satisfied: nested fields use DataLoader.
