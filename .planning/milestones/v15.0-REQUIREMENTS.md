# Milestone v15.0: Service Layer Isolation Requirements

## Goal
Enforce strict service layer isolation across all Kafka listeners and smart aggregators by decoupling them from direct database access and raw SQL execution.

## Requirements

### R1: Aggregator Isolation
- [x] Refactor `ProjectEvents_BatchAggregator`, `TaskEvents_BatchAggregator`, and `TeamEvents_BatchAggregator`.
- [x] Remove direct `db` usage for domain updates.
- [x] Delegate folded data updates to domain service interfaces.

### R2: Intra-Module Listener Decoupling
- [x] Audit all listeners in `auth`, `project`, `task`, and `team` modules.
- [x] Extract raw SQL logic from listeners into the module's service/query boundary.
- [x] Ensure listeners use services instead of direct `db` calls.

### R3: Inter-Module Listener Service Delegation
- [x] Identify listeners that update tables in other modules.
- [x] Replace direct database updates with calls to the public service interfaces of the target modules.
- [x] Remove `import { db }` from these listeners.

### R4: Transaction Boundary Enforcement
- [x] Ensure services manage their own transactions internally.
- [x] Do not pass `trx` objects from listeners/aggregators to services.
- [x] Maintain idempotency and atomicity via the established outbox pattern.

## Success Criteria
- [x] Focused unit tests pass.
- [x] Performance-sensitive write paths preserve batching and chunk continuation semantics.
- [x] `rg "db\." modular-monolith/src/modules/*/internal/listeners` returns zero matches (excluding test files).
- [x] `rg "db\." modular-monolith/src/kafka/smart-aggregator-consumer` returns zero matches (excluding test files).
