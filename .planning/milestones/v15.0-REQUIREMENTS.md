# Milestone v15.0: Service Layer Isolation Requirements

## Goal
Enforce strict service layer isolation across all Kafka listeners and smart aggregators by decoupling them from direct database access and raw SQL execution.

## Requirements

### R1: Aggregator Isolation
- [ ] Refactor `ProjectEvents_BatchAggregator`, `TaskEvents_BatchAggregator`, and `TeamEvents_BatchAggregator`.
- [ ] Remove direct `db` usage for domain updates.
- [ ] Delegate folded data updates to domain service interfaces.

### R2: Intra-Module Listener Decoupling
- [ ] Audit all listeners in `auth`, `project`, `task`, and `team` modules.
- [ ] Extract raw SQL logic from listeners into the module's `internal/queries/` directory.
- [ ] Ensure listeners use query functions instead of direct `db` calls.

### R3: Inter-Module Listener Service Delegation
- [ ] Identify listeners that update tables in other modules.
- [ ] Replace direct database updates with calls to the public service interfaces of the target modules.
- [ ] Remove `import { db }` from these listeners.

### R4: Transaction Boundary Enforcement
- [ ] Ensure services manage their own transactions internally.
- [ ] Do not pass `trx` objects from listeners/aggregators to services.
- [ ] Maintain idempotency and atomicity via the established outbox pattern.

## Success Criteria
- [ ] All unit and e2e tests pass.
- [ ] Performance tests show no degradation.
- [ ] `grep -r "db\." src/modules/*/internal/listeners/` returns zero matches (excluding test files).
- [ ] `grep -r "db\." src/kafka/smart-aggregator-consumer/` returns zero matches (excluding test files).
