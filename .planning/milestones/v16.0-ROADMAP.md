# Roadmap: v16.0 Auto Action Runtime Integration

**Shipped:** 2026-05-22
**Milestone:** v16.0
**Status:** ✅ Shipped

## Summary
Connected domain events to auto-action rule lookup and execution through service boundaries, and exposed auto-action query/mutation APIs with connection pagination and DataLoader batching.

## Phases

### Phase 42: Auto Action Event Consumer
**Goal:** Connect domain events to auto-action rule lookup and execution through service boundaries.
**Status:** Complete (2026-05-22)
**Requirements:** RUNTIME-01, RUNTIME-02, RUNTIME-03, RUNTIME-04, SVC-01, SVC-02

**Accomplishments:**
- Added `AutoActionTaskEventConsumer` subscribing to task events.
- Registered consumer in Kafka registry.
- Implemented `AutoActionService.handleTaskEvents` for trigger matching and pipeline dispatch.
- Removed direct `db` access from pipeline executor (moved to query boundary).
- Added focused runtime tests.

### Phase 43: Auto Action GraphQL API
**Goal:** Expose auto-action query/mutation APIs with connection pagination and DataLoader batching.
**Status:** Complete (2026-05-22)
**Requirements:** GQL-01, GQL-02, GQL-03, GQL-04, GQL-05, PAGE-01, PAGE-02, PAGE-03, SVC-03

**Accomplishments:**
- Implemented GraphQL mutations (`createAutoAction`, `updateAutoAction`, `deleteAutoAction`).
- Implemented GraphQL queries (`autoAction`, `autoActions`).
- Added Relay-style connection pagination for auto-actions.
- Integrated DataLoader for nested field batching.
- Established auth-aware service layer for all GraphQL operations.
