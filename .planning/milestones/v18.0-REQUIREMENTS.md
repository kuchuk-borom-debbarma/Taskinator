# Milestone v18.0 - Requirements: Auto Action Architecture & Performance Evolution

## 1. High Performance Mutations (MUT)
- [x] **MUT-01: Task Single-Query CTEs**: Ensure `insertTask`, `updateTask`, and `deleteTask` use Single-Query CTEs for atomicity and high throughput. 
- [x] **MUT-02: Auto-Action Single-Query CTEs**: Refactor `AutoActionQueries.ts` (`insert`, `update`, `delete`) to use CTEs with outbox writes for audit and event-driven consistency.
- [x] **MUT-03: Modular Query Extraction**: Extract all service-inline queries into `*Queries.ts` to maintain SOLID boundaries.

## 2. Sync/Async Orchestration (ORCH)
- [x] **ORCH-01: Sync Lifecycle Integration**: Synchronous auto-actions (`is_sync: true`) must execute within the request lifecycle of primary mutations (e.g., `task.create`).
- [x] **ORCH-02: Log and Proceed Fault Tolerance**: Primary mutations must succeed even if synchronous auto-actions fail. Errors should be logged, and the primary response returned (Decoupled Fault Tolerance).
- [x] **ORCH-03: Execution Guards**: Enforce a hard limit on the number of synchronous auto-actions triggered per event (e.g., top 10) to prevent API latency spikes.

## 3. Resumable Execution (RES)
- [x] **RES-01: Continuation Cursors**: Async auto-action pipelines must support continuation cursors to resume from the last successful step.
- [x] **RES-02: Kafka Re-emission**: Implement event re-emission with cursors for chunked execution of long-running or high-volume async pipelines.

## 4. Architecture & Clean Code (ARCH)
- [x] **ARCH-01: KISS & Modularity**: Logic paths must be kept "stupidly simple." Avoid complex inheritance or deep nesting.
- [x] **ARCH-02: Naming Standardization**: Resolve the `is_sync` (DB) vs `isAsync` (Code) mismatch. Standardize on `is_sync` / `isSync`.
- [x] **ARCH-03: Loose Coupling**: Services must only interact via well-defined interfaces. No direct cross-module database access.
- [x] **ARCH-04: SOLID Compliance**: Ensure Single Responsibility for all new components (e.g., separate Orchestrator from Execution logic).
