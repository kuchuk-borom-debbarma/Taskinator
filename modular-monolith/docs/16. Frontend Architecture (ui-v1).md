# 16. Frontend Architecture (ui-v1)

The **`ui-v1`** project is a high-performance, modular React application designed as the primary interface for Taskinator. It prioritizes a "Fluent Minimalist" aesthetic (Notion-inspired) and features the **Neural Lattice** for deep architectural discovery.

## 1. Design Philosophy
- **Aesthetic**: Clean grids, high white-space, and professional typography.
- **Workflow**: A dual-navigation model where the **List View** provides high-efficiency management and the **Task Perspective** provides deep dependency context through radial discovery.

## 2. Technical Stack
- **Framework**: [Vite](https://vitejs.dev/) + [React 19](https://react.dev/)
- **State Management**: [TanStack Query](https://tanstack.com/query) (Asynchronous data synchronization).
- **Navigation**: [TanStack Router](https://tanstack.com/router) (URL-based state and deep linking).
- **Animations**: [Framer Motion](https://www.framer.com/motion/) (Spring physics for graph nodes and overlays).
- **Icons**: [Lucide React](https://lucide.dev/).

## 3. Core Architecture: The Adapter Pattern
To ensure the frontend is platform-agnostic and resilient to backend changes, we utilize a strict **Adapter Pattern**.

### A. Interfaces (`src/api/interfaces/`)
The UI components never call an API service directly. Instead, they interact with **Interfaces** that define the contract for each module:
- `ProjectAPI`: Portfolio management.
- `TaskAPI`: Task orchestration and radial neighbourhood discovery.
- `TeamAPI`: Membership and collaboration.

### B. Adapters (`src/api/adapters/`)
Implementations of these interfaces are switched at the provider level:
- **`DummyAdapters`**: (Current) Returns enriched mock data for rapid UI prototyping and edge-case testing.
- **`RealAdapters`**: (Upcoming) Implements GraphQL/Apollo logic for production data.

### C. Injection (`src/context/ApiContext.tsx`)
The `ApiProvider` injects the chosen adapter set into the component tree, ensuring that components like `TaskListView` remain completely unaware of the data's origin.

## 4. Routing & State
We utilize **TanStack Router** to manage the application state through the URL. This enables:
- **Deep Linking**: Share a link directly to a specific task's radial graph view.
- **Breadcrumb Navigation**: Naturally derived from the route tree.
- **Nested Contexts**: The `TaskPerspective` overlay is nested within the `ProjectTasks` route for seamless transitions.

**Route Structure:**
- `/projects`: Project Gallery.
- `/projects/$projectId/tasks`: List View.
- `/projects/$projectId/tasks/$taskId`: Task Perspective (Overlay).

## 5. Neural Lattice (Radial Graph)
The Neural Lattice is a specialized discovery component that visualizes a task's place in the broader project architecture.

- **Discovery vs. Hydration**: The graph first "discovers" neighbours using the server's closure table logic and then "hydrates" edges between all visible nodes.
- **Radial Layout**: Nodes are distributed in concentric circles by depth. Incoming dependencies are placed on the left hemisphere, and outgoing on the right.
- **SVG Rendering**: We use SVG for the Lattice to ensure sharp text rendering and high-performance animations for 100+ visible nodes.
