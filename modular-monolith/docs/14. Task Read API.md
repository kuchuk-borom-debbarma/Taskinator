
# 📋 Task Module - Read API

---

## 🎯 Goal

Expose a paginated list of tasks for a given project.
Sorted chronologically by `created_at`, with stable bi-directional cursor navigation.

---

## 🧩 GraphQL API

### Query

```graphql
projectTasks(
  projectId: ID!
  first: Int
  after: String
  last: Int
  before: String
): ProjectTaskConnection!
```

### Types

```graphql
type ProjectTask {
  id: ID!
  projectId: ID!
  teamId: ID
  memberId: ID
  title: String!
  description: String!
  status: String!
  version: Int!
  lastEventId: ID
  createdBy: ID!
  updatedBy: ID!
  createdAt: String!
  updatedAt: String!

  # Resolved
  project: Project
  team: Team
}

type ProjectTaskEdge {
  node: ProjectTask!
  cursor: String!
}

type ProjectTaskConnection {
  edges: [ProjectTaskEdge!]!
  pageInfo: PageInfo!
}
```

> **Note:** `status` is a free-form `String` (e.g. `"TODO"`, `"IN_PROGRESS"`, `"DONE"`).
> No enum is enforced at the API layer — validation is handled at the service layer.

---

## 📑 Pagination Strategy

**Temporal Pagination** — ordered by `(created_at DESC, id DESC)`.

### Cursor Format

```
<ISO 8601 timestamp>|<UUID>
```

Example:
```
2026-04-16T10:00:00.000Z|3f2f1a2b-...
```

### Rules

| Param | Direction | SQL Condition |
|---|---|---|
| `first` + `after` | Forward | `created_at < cursor_date OR (= AND id < cursor_id)` |
| `last` + `before` | Backward | `created_at > cursor_date OR (= AND id > cursor_id)` |

- Default page size: **10**
- Max page size: **50** (hard-capped in service)
- Deterministic tie-breaking via UUID ensures no skipped rows on equal timestamps

## 🔐 Authorization

Every query checks membership at the database level:

```sql
WITH auth_check AS (
  SELECT 1 FROM project WHERE id = $projectId AND fk_user_id = $userId
  UNION ALL
  SELECT 1 FROM project_member WHERE fk_project_id = $projectId AND fk_user_id = $userId
  LIMIT 1
)
```

Only project owners and members can list tasks.

---

## 🗄️ Data Layer

### `getTasksPage` (in `TaskQueries.ts`)

Single database trip. Auth check runs inline via CTE.
Returns paginated rows with cursor metadata computed in TypeScript.

### `getTasksByIds` (in `TaskQueries.ts`)

Batch fetch used by the `task` DataLoader.
Accepts an array of UUIDs and resolves them in a single `WHERE id = ANY(...)` query.
Authorization is enforced per-task via project membership subqueries.

---

## 🔄 DataLoader

Registered in `src/graphql/loaders.ts`:

```ts
task: new DataLoader<string, ProjectTask | null>(async (ids) => {
    const tasks = await taskService.getTasksByIds(userId, ids as string[]);
    const map = new Map(tasks.map((t: ProjectTask) => [t.id, t]));
    return ids.map((id) => map.get(id) || null);
})
```

Used to hydrate individual task nodes across graph views without N+1 queries.

## 🏗️ Layer Map

```
GraphQL Resolver (task.ts)
  └── taskService.getTasks()
        └── getTasksPage() [SQL, single trip]
              └── project_task table
```

```
DataLoader (loaders.ts → task)
  └── taskService.getTasksByIds()
        └── getTasksByIds() [SQL, batched ANY()]
```

## ⚠️ Guardrails

- Max limit: **50** tasks per page
- Backward pagination (`last` / `before`) reverses result order in TypeScript after slicing
- `hasMore` is detected via `LIMIT n+1` trick — avoids separate COUNT query
