# Automation System Design

## What is it?
A reactive system where things happen automatically when something occurs in the app. No user intervention needed.

---

## Three Layers

**Trigger** → something happens (e.g. a task is completed)
**Condition** → optional filter to narrow when it applies (e.g. only if priority is high)
**Action** → what runs as a result (e.g. notify the team)

---

## Key Decisions Made

- Triggers, conditions, and actions are all **hardcoded** — no custom logic by users
- The backend ships a **template** per trigger that tells the frontend exactly which conditions and actions are allowed for it
- Actions can run **sync or async** — async goes through the existing message broker
- Automations are **scoped** — a user attaches an automation to a project, team, or task
- **Conditions** are chainable with AND / OR / NOT — hard limit of 5 conditions per automation
- **Actions** are chainable in order — hard limit of 10 actions per automation
- **Async actions can only chain with async, sync with sync** — no mixing
- One **async/sync toggle** per automation
- No batching or grouping logic for now — future consideration
