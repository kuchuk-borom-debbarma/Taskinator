# Task Automations: Conditions & Actions

This document defines the full list of supported **Conditions** and **Actions** available when creating automations scoped to a **Task**.

All automations for tasks are **evaluated asynchronously** against two snapshots of the task: `oldState` (before the mutation) and `newState` (after the mutation).

---

## The Rule Structure

An automation contains an **ordered array of Rules**. Each rule is evaluated in sequence — if conditions pass, actions execute immediately before the next rule is evaluated.

```json
[
  {
    "when": {
      "match": "ALL",
      "conditions": [ ... ]
    },
    "then": [ ... ]
  }
]
```

---

## Conditions (`when`)

Conditions are defined as a **RuleGroup** — a recursive logical tree.

### RuleGroup

```json
{
  "match": "ALL | ANY",
  "conditions": [ <Condition | RuleGroup>, ... ]
}
```

- `ALL` — Every child must pass (AND logic).
- `ANY` — At least one child must pass (OR logic).
- Groups can be **nested infinitely** for complex logic.

### Condition

```json
{ "field": "<task field>", "op": "<operator>", "value": <any> }
```

### Supported Fields

All fields refer to properties on the **task entity** itself.

| Field | Type | Description |
| :--- | :--- | :--- |
| `status` | `string` | Task status (e.g. `TODO`, `IN_PROGRESS`, `DONE`) |
| `priority` | `string` | Task priority level |
| `memberId` | `string \| null` | Assigned member ID |
| `teamId` | `string \| null` | Assigned team ID |
| `parentTaskId` | `string \| null` | Parent task ID |
| `title` | `string` | Task title |

### Supported Operators

#### Equality & Comparison
| Operator | Description |
| :--- | :--- |
| `EQUALS` | `newState[field] === value` |
| `NOT_EQUALS` | `newState[field] !== value` |
| `GREATER_THAN` | `newState[field] > value` |
| `LESS_THAN` | `newState[field] < value` |

#### Arrays & Strings
| Operator | Description |
| :--- | :--- |
| `IN` | `value.includes(newState[field])` |
| `NOT_IN` | `!value.includes(newState[field])` |
| `CONTAINS` | `newState[field].includes(value)` |

#### State Deltas *(The Engine's Superpower)*
| Operator | Description |
| :--- | :--- |
| `HAS_CHANGED` | Field was modified at all (`oldValue !== newValue`) |
| `CHANGED_TO` | Field changed specifically **to** `value` |
| `CHANGED_FROM` | Field changed specifically **from** `value` |

#### Existence
| Operator | Description |
| :--- | :--- |
| `IS_NULL` | Field is `null` or `undefined` |
| `IS_NOT_NULL` | Field is not `null` or `undefined` |

### Example

*"If status just changed to DONE AND (priority is HIGH OR the task was previously unassigned)"*

```json
{
  "match": "ALL",
  "conditions": [
    { "field": "status", "op": "CHANGED_TO", "value": "DONE" },
    {
      "match": "ANY",
      "conditions": [
        { "field": "priority", "op": "EQUALS", "value": "HIGH" },
        { "field": "memberId", "op": "CHANGED_FROM", "value": null }
      ]
    }
  ]
}
```

## Actions (`then`)

Actions are executed **sequentially** in the order they are defined. The current V1 action type is `UPDATE_TASK`.

### Action Structure

```json
{
  "type": "UPDATE_TASK",
  "target": "<target>",
  "targetIds": ["<uuid>", ...],
  "params": { "<field>": "<value>", ... },
  "shouldPropagate": true
}
```

| Field | Required | Description |
| :--- | :--- | :--- |
| `type` | ✅ | Action type. Currently only `UPDATE_TASK`. |
| `target` | ✅ | Which tasks to apply the update to. |
| `targetIds` | Only for `SPECIFIC_TASKS` | Explicit list of task UUIDs to update. |
| `params` | ✅ | The fields to update, e.g. `{ "status": "DONE" }`. |
| `shouldPropagate` | Optional (default: `true`) | If `false`, the update is applied silently — no further automation events are emitted for the updated tasks. Prevents infinite loops. |

### Supported Targets

| Target | Description | DB Query Required |
| :--- | :--- | :--- |
| `@self` | The task that triggered the event | ❌ No |
| `@parent` | The immediate parent task | ✅ Yes |
| `@children` | All direct sub-tasks | ✅ Yes |
| `@descendants` | All nested sub-tasks (entire tree) | ✅ Yes (materialized path) |
| `SPECIFIC_TASKS` | Explicit list of task IDs via `targetIds` | ❌ No |

### Example

*"Set self to IN_PROGRESS, then set all direct children to BLOCKED"*

```json
[
  {
    "type": "UPDATE_TASK",
    "target": "@self",
    "params": { "status": "IN_PROGRESS" },
    "shouldPropagate": true
  },
  {
    "type": "UPDATE_TASK",
    "target": "@children",
    "params": { "status": "BLOCKED" },
    "shouldPropagate": false
  }
]
```
