# Automation Engine - Task Scope

This document specifies the conditions and actions available for automations within the **Task** scope.

## 1. Context Snapshots
Every Task-scoped automation is provided with two state snapshots for evaluation:
- `oldState`: The full task object before the update.
- `newState`: The full task object after the update.

---

## 2. Conditions (The "IF")

### 2.1 Status Transitions
- **Changed From X**: `oldState.status == x`
- **Changed To Y**: `newState.status == y`
- **Full Transition (X to Y)**: `oldState.status == x && newState.status == y`

### 2.2 Team & Assignment
- **Is Assigned**: Task has any team assigned (`fk_team_id != null`).
- **Is Assigned to Team X**: Matches a specific Team ID.
- **Is Unassigned**: Task has no team.
- **Unassigned from Team X**: Task moved from Team X to a null state.
- **Assignment Updated**: Team was changed to a new value or unassigned.

---

## 3. Actions (The "THEN")
Actions are side-effects applied when conditions are met.

- **Set Status**: Update the current task status.
- **Set Assignment**: Reassign the task to a different team or member.
- **Create Task**: Generate a new related child task.
- **Delete Task**: Remove the task or mark as archived.

---

## 4. Advanced / Hierarchical Automations (Refined for Phase 2)
These conditions and actions involve relational lookups and subtree propagation.

### 4.1 Hierarchical Conditions
- **Has Children**: The task has one or more sub-tasks.
- **Has X Children**: The task has an exact count of sub-tasks.
- **Has Specific Children**: Checks for specific Child IDs `[X, Y, Z]`.
- **Parent Related**: Checks for parent existence, status, or identity.

### 4.2 Hierarchy Actions (Targeting)
Actions can be targeted beyond the triggering task:
- **Target: CHILDREN**: Apply action to direct child tasks.
- **Target: DESCENDANTS**: Apply action to the entire subtree.

*Note: For these actions, the engine provides the Parent Snapshots as input to the children's execution context.*
