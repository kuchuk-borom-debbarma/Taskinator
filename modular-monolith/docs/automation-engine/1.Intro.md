# Automation Engine - Introduction

The Taskinator Automation Engine is a high-performance, event-driven IFTTT system designed to automate workflows across the platform.

## 1. Core Philosophy
The engine operates on a **Detect -> Evaluate -> Execute** loop. It is designed to handle up to 10k RPS by leveraging a stateless evaluation model based on task snapshots.

## 2. Scopes
Automations are organized into three primary scopes to balance performance and flexibility:

- **Project Scope**: Rules that apply to all entities within a specific Project.
- **Team Scope**: Rules that govern team-level assignments and workflows.
- **Task Scope**: Rules specific to the lifecycle of individual tasks and their hierarchies.

*Note: Initial development focuses on the **Task Scope**.*

---

## 3. Traceability & Observability

To provide transparency into how automations operate, the engine implements a **Flow Tracking** system.

### 3.1 Correlation ID
Every automation chain is assigned a unique `correlationId` at its point of origin:
- **Initiation**: When a user action or system event first fires a trigger, a UUID is generated.
- **Propagation**: This `correlationId` is carried forward into all sequential actions and cascading triggers (even across recursions).
- **Visualization**: By grouping events by this ID, users can view a "Tree Map" of how a single update rippled through the project.

### 3.2 Logging
Every successful evaluation and action execution is logged with its `correlationId`, allowing for simplified debugging of complex, recursive workflows.
