# Automation Engine

The Automation Engine is an event-driven, rule-based **IFTTT** (If This Then That) system built into Taskinator. It allows users to define automations that automatically react to changes in Tasks, Projects, and Teams.

## What It Does

When something changes in the system (e.g. a task's status is updated), the engine:

1. Evaluates a set of user-defined **Rules** against the before and after state of the entity.
2. If the conditions of a rule pass, it executes the associated **Actions**.

## Core Concepts

| Concept | Description |
| :--- | :--- |
| **Automation** | A stored record owned by a user, scoped to a project/task/team. Contains an ordered list of Rules. |
| **Rule** | A single `{ when, then }` block. `when` defines the condition tree, `then` defines the actions. |
| **RuleGroup** | A logical condition tree using `match: ALL` (AND) or `match: ANY` (OR). Can be nested. |
| **Condition** | A single predicate: `{ field, op, value }` evaluated against old and new state. |
| **Action** | A mutation to apply when conditions pass, e.g. update a task's status. |

## Execution Model

All automations execute **out-of-band** via the event system. When a task is updated:

- The mutation completes immediately and returns to the client.
- An event is published carrying `oldState` and `newState` snapshots.
- The automation engine evaluates rules and dispatches actions out-of-band via Kafka.
- UI corrections are pushed back in real-time via the existing SSE channel.

## Scopes

Automations can target three scopes:

- **Task** — Reacts to changes on a specific task.
- **Team** — Reacts to changes on any task assigned to a given team.
- **Project** — Reacts to changes on any task within a project.
