# Automation Module

This document describes the structure and responsibilities of the `automation` module located at `src/modules/automation/`.

---

## Overview

The `automation` module is a self-contained service module that owns all CRUD operations for automation records, exposes the engine internals, and provides DataLoader-compatible batch query methods for GraphQL.

---

## Directory Structure

```
src/modules/automation/
├── AutomationService.ts          — Public service interface
├── index.ts                      — Exports the singleton automationService instance
│
└── internal/
    ├── AutomationServiceImpl.ts  — Concrete implementation of AutomationService
    ├── AutomationQueries.ts      — All Kysely DB queries (CRUD + batch loaders)
    │
    └── engine/
        ├── DSL.ts                — TypeScript type definitions for the Rule DSL
        ├── ConditionEvaluator.ts — Stateless rule group evaluator
        └── ActionDispatcher.ts   — (Planned) Resolves targets and executes actions
```

---

## `AutomationService` Interface

The public API of the module. Other parts of the codebase (resolvers, listeners) only depend on this interface, never on the implementation.

| Method | Description |
| :--- | :--- |
| `addAutomation(data)` | Creates a new automation. Validates DSL structure at write time. |
| `updateAutomation(data)` | Updates an automation. Re-validates DSL on rules change. |
| `deleteAutomation(data)` | Deletes an automation. Checks ownership. |
| `getAutomationsByFilter(data)` | Paginated cursor-based query with flexible filters. |
| `getAutomationsByTaskIds(ids)` | Batch loader for task-scoped automations. |
| `getAutomationsByProjectIds(ids)` | Batch loader for project-scoped automations. |
| `getAutomationsByTeamIds(ids)` | Batch loader for team-scoped automations. |

---

## Authorization Model

All write operations (add, update, delete) require the `userId` to be either:
- The **project owner** (`project.fk_user_id`)
- A **project member** (`project_member.fk_user_id`)
- The **original creator** of the automation (`automations.actor_id`)

This is enforced inside `AutomationQueries.ts` using raw SQL auth checks.

---

## GraphQL Integration

The module exposes automations through the GraphQL layer via:

- **Schema**: `src/graphql/schema/automation.graphql`
- **Resolvers**: `src/graphql/resolvers/automation.ts`
- **DataLoaders**: Registered in `src/graphql/loaders.ts`
  - `context.loaders.taskAutomations`
  - `context.loaders.projectAutomations`
  - `context.loaders.teamAutomations`

This means `task.automations`, `project.automations`, and `team.automations` are all resolved with a single batched DB query per request — no N+1 issues.
