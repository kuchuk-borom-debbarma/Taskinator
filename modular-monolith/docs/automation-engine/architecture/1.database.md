# Database Schema

This document describes the database tables that underpin the Automation Engine.

---

## `automations` Table

The core table. Each row represents one automation owned by a user, scoped to a project, and optionally pinned to a specific task or team.

```sql
CREATE TABLE automations (
    id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    fk_project_id UUID NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    actor_id    TEXT NOT NULL,              -- the user who created this automation
    target_scope TEXT NOT NULL,            -- 'TASK' | 'TEAM' | 'PROJECT'
    fk_task_id  UUID REFERENCES project_task(id) ON DELETE CASCADE,   -- set when target_scope = 'TASK'
    fk_team_id  UUID REFERENCES project_team(id) ON DELETE CASCADE,   -- set when target_scope = 'TEAM'
    rules       JSONB NOT NULL,            -- Array of Rule objects (see DSL docs)
    is_active   BOOLEAN NOT NULL DEFAULT TRUE,
    created_at  TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_automations_project ON automations(fk_project_id);
CREATE INDEX idx_automations_task    ON automations(fk_task_id);
CREATE INDEX idx_automations_team    ON automations(fk_team_id);
```

### Column Notes

| Column | Notes |
| :--- | :--- |
| `target_scope` | Determines which FK is populated — only `fk_task_id` or `fk_team_id`, not both. |
| `rules` | JSONB array of `Rule` objects, validated at write time. See [2.task.md](../2.task.md) for the full DSL. |
| `actor_id` | The `userId` of the creator. Used for ownership checks on update/delete. |
| `is_active` | Soft toggle. Inactive automations are skipped during evaluation. |



## Event Payload (Outbox)

The automation engine is triggered by outbox events published to Kafka. The payload written to the `outbox_events` table carries:

```json
{
  "taskId": "<uuid>",
  "projectId": "<uuid>",
  "teamId": "<uuid | null>",
  "actorId": "<userId>",
  "correlationId": "<uuid>",
  "depth": 0,
  "oldState": { ... },
  "newState": { ... }
}
```

| Field | Description |
| :--- | :--- |
| `correlationId` | Traces an entire automation cascade chain across multiple events. |
| `depth` | Increments on each cascade. Capped at **5** to prevent infinite loops. |
| `oldState` | Full snapshot of the task BEFORE the mutation. |
| `newState` | Full snapshot of the task AFTER the mutation. |
