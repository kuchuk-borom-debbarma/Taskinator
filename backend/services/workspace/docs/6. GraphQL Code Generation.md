# GraphQL Code Generation Guide

This project uses the **Netflix DGS Codegen** plugin to automatically generate Kotlin types and constants from the GraphQL schema. This ensures type safety and decouples our internal Domain models from the external API contract.

## 1. Prerequisites

The configuration is already defined in `build.gradle.kts`. It uses:
- **Plugin**: `com.netflix.dgs.codegen` version `8.3.0`
- **Gradle**: 9.3+
- **Schema Location**: `src/main/resources/graphql/`

## 2. Configuration Details

The code generation is configured in `build.gradle.kts` using the `GenerateJavaTask` block:

```kotlin
tasks.withType<com.netflix.graphql.dgs.codegen.gradle.GenerateJavaTask> {
    // The base package for all generated classes
    packageName = "dev.kuku.taskinator.generated"
    
    // Path to your .graphql or .graphqls files
    schemaPaths = mutableListOf("${projectDir}/src/main/resources/graphql")
}
```

## 3. How to Generate Code

Run the following command from the root of the workspace service:

```bash
./gradlew generateJava
```

> **Note**: Even though the task is named `generateJava`, it detects the Kotlin plugin and generates `.kt` files automatically.

## 4. Where are the files?

After running the command, generated files are located in:
`build/generated/sources/dgs-codegen/dev/kuku/taskinator/generated/`

The two most important sub-packages are:
1.  `types/`: Contains Kotlin data classes matching your GraphQL types (e.g., `Project`, `Team`, `User`).
2.  `DgsConstants.kt`: Contains constants for all Type names and Field names.

## 5. Usage in Resolvers

### A. Using Types
Always map your internal domain models to the generated types in your data fetchers.

```kotlin
@DgsQuery
fun project(@InputArgument id: String): Project? {
    val internalProject = projectService.getProjectById(id, "user-id") ?: return null
    
    // Convert Domain -> Generated Type
    return Project(
        id = internalProject.id,
        name = internalProject.name,
        createdAt = internalProject.createdAt.toString()
    )
}
```

### B. Using Constants
To avoid typos and get compile-time safety, use `DgsConstants` in your `@DgsData` annotations.

```kotlin
import dev.kuku.taskinator.generated.DgsConstants

@DgsData(
    parentType = DgsConstants.PROJECT.TYPE_NAME, 
    field = DgsConstants.PROJECT.Teams
)
fun getTeams(dfe: DgsDataFetchingEnvironment): List<Team> {
    // ... logic
}
```

## 6. Best Practices
1.  **Run regularly**: Run `./gradlew generateJava` every time you modify `schema.graphql`.
2.  **Don't Edit**: Never manually edit files in `build/generated`. They are overwritten every time you build.
3.  **Git**: The `build/` directory is ignored by Git, so teammates should run the generate command after cloning.
