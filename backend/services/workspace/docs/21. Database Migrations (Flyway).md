# Database Migrations (Flyway)

The Workspace Service uses **Flyway** to manage its PostgreSQL schema. This ensures that every developer and environment (Dev, Staging, Prod) is running on the exact same database structure.

## 📁 Migration Location
All migration scripts are located in:
`backend/services/workspace/src/main/resources/db/migration/`

## 📝 Naming Convention
Flyway uses a strict naming convention to determine execution order:
**`V<Number>__<Description>.sql`**

- **V**: Prefix for Versioned migrations.
- **Number**: Sequential version number (e.g., `1`, `2`, `2.1`).
- **`__`**: Two underscores separate the version from the description.
- **Description**: Snake_case description (e.g., `add_task_priority`).

**Example:** `V2__add_index_to_tasks.sql`

---

## 🚀 How to Create a New Migration

1.  **Define your Table in Kotlin:** Update the Exposed `Table` object in `Tables.kt` first (this keeps the code in sync with the DB).
2.  **Generate SQL:** Create a new `.sql` file in the migration directory.
3.  **Run Migrations:** Simply start the application. Spring Boot runs Flyway automatically on startup.
    ```bash
    ./gradlew bootRun
    ```

---

## ⚡ High-Performance Best Practices (10k RPS)
Since this service is optimized for extreme scale, follow these rules for migrations:

1.  **Non-Blocking DDL:** Avoid operations that lock the whole table for a long time (like adding a column with a complex default value on a table with millions of rows).
2.  **Indices:** Always create indices for foreign keys (`fk_...`) and columns used in `WHERE` clauses.
3.  **Idempotency:** Ensure your SQL scripts are clean. Flyway runs each script exactly once.
4.  **No Down-Migrations:** We follow a "Forward Only" approach. If you make a mistake in `V3`, create `V4` to fix it.

## 🛠 Troubleshooting

### Migration Checksum Failure
If you modify a migration file that has **already been executed**, Flyway will crash with a `Checksum mismatch`.
- **Solution:** Never modify an existing migration file. Create a new one.
- **Emergency Fix (Dev only):** If you must change a dev-only script, run:
  ```bash
  psql -U user -d workspace -c "DELETE FROM flyway_schema_history WHERE version = 'X';"
  ```

### The `flyway_schema_history` Table
Flyway creates a table in your database to track which migrations have run. You can query it to see the status:
```sql
SELECT version, description, success FROM flyway_schema_history;
```

## 🔌 Manual Commands (Optional)
If you want to run Flyway without starting the whole Spring Boot app, you can use the Gradle plugin (if configured) or the Flyway CLI against your local Docker DB:
```bash
# Example using environment variables
FLYWAY_URL=jdbc:postgresql://localhost:5432/workspace FLYWAY_USER=user FLYWAY_PASSWORD=password flyway migrate
```
