# 10. Read Path Optimization (GraphQL DataLoaders & Hybrid Fetching)

To support the high-scale writes designed in the previous documents, the **Read Path** must be equally efficient. This document outlines the strategy for solving the N+1 problem and ensuring low-latency reads using GraphQL DataLoaders and a Hybrid Cache/DB fetching model.

## 1. The N+1 Problem in Taskinator
With recursive tasks and complex relationships (Owner, Project, Team), a single GraphQL query could trigger hundreds of database round-trips.
*   **Without DataLoaders:** Fetching 100 tasks with their owners = 1 query for tasks + 100 queries for owners = **101 total queries**.
*   **With DataLoaders:** Fetching 100 tasks with their owners = 1 query for tasks + 1 batch query for owners = **2 total queries**.

---

## 2. Low-Level Implementation: MappedBatchLoader
We use `MappedBatchLoader` to ensure type safety and handle cases where the database might return results in a different order than requested.

### The Hybrid DataFetcher Logic
When a DataLoader is invoked to fetch a batch of IDs (e.g., `ownerIds` or `parentTaskIds`):

1.  **Phase 1: Redis MGET (L1 Cache)**
    Execute a single Redis `MGET` for all requested IDs. This captures "In-Flight" data from the Ingest-Buffer-Drain path.
2.  **Phase 2: Identification**
    Compare the IDs found in Redis against the requested list to identify "Cache Misses."
3.  **Phase 3: Database Batch (L2 Storage)**
    Execute a single `SELECT ... WHERE id IN (...)` for the missing IDs.
4.  **Phase 4: Consolidation**
    Merge results from Redis and the DB into a single Map to satisfy the GraphQL request.

---

## 3. Recursive Task Resolution
Taskinator allows tasks to be nested up to 50 levels deep. DataLoaders optimize this "Tree Walk":

*   **Breadth-First Batching:** The DataLoader engine waits for all fields at a specific depth of the tree to be requested before executing the batch.
*   **Complexity Limit:** A query fetching 5 levels of tasks will execute exactly **5 batch queries**, regardless of the total number of tasks in the tree.

```kotlin
@DgsDataLoader(name = "subtasks")
class SubtaskDataLoader(val taskService: TaskService) : MappedBatchLoader<UUID, List<Task>> {
    override fun load(keys: Set<UUID>): CompletionStage<Map<UUID, List<Task>>> {
        return CompletableFuture.supplyAsync {
            // Fetch all children for all parent IDs in one query
            taskService.findChildrenByParentIds(keys)
        }
    }
}
```

---

## 4. Federated DataLoaders (Cross-Service)
Since Taskinator uses **Apollo Federation**, some data (like `User` profiles) lives in the **Identity Service**, while `Tasks` live in the **Workspace Service**.

*   **The Problem:** The Workspace service cannot query the Identity DB directly.
*   **The Solution:** The DataLoader's `load` function calls the Identity Service via a high-performance gRPC or internal HTTP/2 batch endpoint.
    *   *Batch Request:* `POST /internal/users/batch-find { ids: [...] }`
    *   *Result:* The DataLoader transparently hides the network latency from the GraphQL schema.

---

## 5. Caching Strategy & Scope
*   **Request-Scoped Cache:** DataLoaders maintain a cache **only for the duration of a single GraphQL request**. This ensures that if the same User is requested 10 times in one query, the DB is hit only once.
*   **Zero Stale Data:** By scoping the cache to the request, we avoid the complexity of cache invalidation that plagues global caches.

---

## 6. Performance Tuning
*   **Max Batch Size:** Set to 1,000. If a query requests 5,000 entities, the DataLoader splits them into 5 parallel batches of 1,000 to avoid hitting PostgreSQL's limit on `IN` clause parameters.
*   **Dispatcher Threads:** Use a dedicated `virtual-thread-per-task` (Java 21) or a custom ThreadPool for DataLoaders to ensure that slow DB queries in one batch don't block the entire API.

## 7. Summary of Read Path Flow
1.  **GraphQL Engine** parses query.
2.  **DataFetchers** return `CompletableFuture` (promises).
3.  **DataLoader Dispatcher** collects all promises at the current level.
4.  **BatchLoader** performs Hybrid Fetch (Redis -> DB).
5.  **Promises** are resolved; results are returned to the user.
