# 18. Universal Cascading Cleanup Strategy

In a system targeting **10k RPS**, synchronous cascading deletes (`ON DELETE CASCADE`) are dangerous. They create long-running transactions and lead to "Head-of-Line Blocking" in Kafka partitions.

Taskinator implements a **Universal Reactive Cascading Cleanup** strategy. Deletions at *any* node in the domain hierarchy trigger targeted, event-driven cleanup cascades.

## 1. The Cascade Matrix

| Trigger Action | Synchronous API Action | Emitted Domain Event | Async Cleanup Cascade (The "Drain") |
| :--- | :--- | :--- | :--- |
| **Delete Project** | Mark/Delete Project & Project Members | `ProjectDeleted` | 1. Chunky Delete ALL Teams.<br>2. Chunky Delete ALL Tasks. |
| **Remove Member** | Delete Project Members | `ProjectMembersRemoved` | 1. Chunky remove from `project_team_members`.<br>2. Chunky unassign from `project_tasks`. |
| **Delete Team** | Fetch Descendants -> Delete Root Team | `TeamDeleted(descendantIds)` | 1. Chunky Delete sub-teams & members.<br>2. Chunky unassign tasks for deleted teams. |
| **Delete Task** | Fetch Path -> Delete Root Task | `TaskDeleted(path)` | 1. Chunky Delete sub-tasks using `path LIKE '.../%'`. |

---

## 2. Architectural Principles

1.  **State Capture Before Deletion:** When deleting a node with children (like a Team or Task), the API must capture the "Sub-tree Scope" (e.g., the Task's `path` or the Team's descendant IDs via the closure table) *before* deleting the root node, passing this scope into the Kafka event.
2.  **Granular Fan-out:** Domain events (`TeamDeleted`) are translated by the orchestrator into specific internal `CleanupEvent` tasks (`SubTeamsPurgeRequested`, `TeamTasksUnassignRequested`).
3.  **Idempotent Exhaustion:** The "Chunky Delete" queries use `LIMIT`. Consumers pass the full scope (e.g., a list of IDs) to the query. The query deletes a chunk, and if rows were affected, the consumer re-emits the event with the *same* scope. The query will naturally ignore already-deleted rows in the next chunk, making it perfectly idempotent.

## 3. Internal Cleanup Events

```kotlin
sealed class CleanupEvent {
    data class ProjectPurgeRequested(val projectId: String)
    data class SubTasksPurgeRequested(val projectId: String, val parentPath: String)
    data class SubTeamsPurgeRequested(val projectId: String, val teamIds: List<String>)
    data class MemberCleanupRequested(val projectId: String, val memberIds: List<String>)
    data class TeamTasksUnassignRequested(val projectId: String, val teamIds: List<String>)
}
```
